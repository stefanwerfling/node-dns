# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**dns2ts** — a pure TypeScript DNS server and client library with zero production dependencies. Implements DNS over UDP, TCP, TLS (DoT, RFC 7858), and HTTPS (DoH, RFC 8484), client + server.

## Build & Development Commands

```bash
npm install              # Install dev dependencies
npx tsc                  # Compile TypeScript (src/ -> dist/)
npm test                 # Compile + run all tests (tsc && node dist/Test)
npm run lint             # ESLint check
npm run fix              # ESLint auto-fix
```

Example servers (run after compiling):
```bash
npm run example-server-udp    # Start UDP DNS server
npm run example-server-tcp    # Start TCP DNS server
```

## Architecture

### Module Layout (src/)

- **Lib/HostsFile.ts** — `/etc/hosts` parser + lookup. `HostsFile.parse(content)` / `HostsFile.fromFile(path?)` returns a `HostsFile` instance. Tolerant: malformed lines (no IP, no name, bad address) silently skipped. Names lowercased on parse, lookup is case-insensitive + trailing-dot tolerant. IPv4 (`A`) vs IPv6 (`AAAA`) auto-detected from the address. `lookup(name, type)` returns discriminated union `{kind: 'match', records} | {kind: 'nodata'} | {kind: 'miss'}` — match has at least one record of the requested type, nodata means name is in the file but no record of that type (glibc strict semantics — file is authoritative for present names), miss means name not in file. `asResolverBackend(fallback)` is the StubResolver-shaped adapter: synthesizes NOERROR + AA=1 response on match, NOERROR + empty answers (NODATA shape per RFC 1034 §4.3.2 / RFC 2308 §2.2) on nodata WITHOUT falling through, and only invokes `fallback` on miss. `merge(other)` stacks tables — earlier entries win on collision. `ttl` option (default 0, matches glibc no-cache behavior) stamps synthesized records. **Reload + watch**: `fromFile()` remembers the source path on `_sourcePath`; `reload(path?)` re-reads, parses, and atomically swaps `_entries`/`_byName` under the same instance — closures returned by `asResolverBackend()` see the new state automatically since they capture `this`. `watch(options): HostsFileWatchHandle` wraps `fs.watch` with debounce (default 100ms) and rename-recovery (re-opens the watcher after editor write-and-rename so the dead inode doesn't pin the watcher). `HostsFileWatchHandle` exposes `close()` (idempotent), `reloadNow()` (bypass debounce), `path` and `closed` getters. Errors during reload go to `options.onError` if provided; otherwise `ENOENT`/`EACCES`/`EPERM` are silently swallowed (glibc tolerance) and everything else becomes a `process.emitWarning`. The debounce timer is `unref`'d so the watcher doesn't block process exit on its own.
- **Lib/NetworksFile.ts** — `/etc/networks` parser (`networks(5)`). `NetworksFile.parse(content)` / `NetworksFile.fromFile(path?)` returns an instance with `entries` plus `lookupByName(name)` (case-insensitive + alias-aware) and `lookupByAddress(addr: string | Buffer)`. Addresses expand abbreviations to full dotted-quad (`127` → `127.0.0.0`, `192.168.1` → `192.168.1.0`). IPv4-only per spec. Tolerant: comments via `#`, malformed lines silently skipped, ENOENT/EACCES/EPERM swallowed by `fromFile` like glibc. `merge(other)` stacks (earlier wins). **Not** wired into SystemResolver — `resolver(5)` doesn't consult `/etc/networks`; the parser is a standalone utility for observability / reverse-name pretty-printing tools.
- **Lib/ResolvConf.ts** — resolver(5) `/etc/resolv.conf` parser. `ResolvConf.parse(content)` returns `{nameservers, search, domain?, sortlist, options}`; `fromFile(path?)` is the convenience that reads the standard path. Tolerant: unknown directives are skipped silently, unknown `options` tokens land in `options.unknown`, malformed numeric options fall back to resolver(5) defaults. Last-write-wins for `search` per RFC §3.
- **Lib/** — Low-level I/O and parsers: `BufferReader`/`BufferWriter` for bit-level DNS wire format parsing, `SocketReader` for TCP stream framing (accepts an optional `initialBuffer` so pre-consumed bytes can be fed in), `ZoneParser` for RFC 1035 master file parsing (tokenizer with parens/quotes/comments, `$ORIGIN`/`$TTL`/`$INCLUDE`/`@`, RFC §5.1 leading-whitespace owner-name inheritance, `$INCLUDE` accepts an optional origin override and recurses with a fresh nested state — directives in the included file do not leak back to the parent — file content is read via `fs.readFileSync` against `basePath` by default; pass `includeResolver: (filename, basePath) => string` to load from custom sources; cycles are detected and rejected, RDATA for A/AAAA/NS/CNAME/DNAME/PTR/MX/TXT/SOA/SRV/CAA plus DNSKEY/DS/CDS/CDNSKEY/SSHFP/TLSA/SMIMEA/NAPTR/NSEC/NSEC3/RRSIG/SVCB/HTTPS/HINFO/URI/ZONEMD/OPENPGPKEY/CERT/LOC (LOC accepts the seven-field raw integer form; deg/min/sec presentation parsing is out of scope; OPENPGPKEY + CERT consume base64 cert/key bytes and store as hex internally) — base32hex helper for NSEC3 next-hashed-owner, generic `TYPEnnn` mnemonic via RFC 3597, `_typeMnemonicToNumber` mapping for NSEC/NSEC3/RRSIG type-bit-maps, RFC 9460 §2.1 SVCB presentation form with `key=value`/quoted/`key=`-then-quoted-token glue and `keyN=` round-trip via `unknown[]`), `Random0x20` (RFC 5452 §9.2 case randomization — `scramble` flips ASCII letters via CSPRNG, `matches` is the case-sensitive verifier; wired into UDPClient/TCPClient via `use0x20: true`), `Bailiwick` (RFC 5452 §6 — `contains(zone, name)` membership predicate, `filter(packet, zone)` strips out-of-zone answer/authority/additional records while preserving questions and EDNS OPT), `Rrl` (RFC 5358-style Response Rate Limiting — token-bucket per (prefix, qtype) bucket; `check(clientIp, qtype, now?)` returns `'allow'|'drop'|'truncate'`; refills at `maxRate` per second, capped at `capacity`; IPv4/IPv6 prefixing default to `/24`/`/56`; slip ratio default 2 — every Nth over-budget query gets a TC=1 hint so legitimate clients fall back to TCP, where source spoofing is hard; `maxBuckets` FIFO-evicts oldest entries to bound memory; built-in IPv4/IPv6 parsers handle `::`-compression and `::ffff:1.2.3.4` IPv4-tail form. UDPServer wires it via `udp.rrl: Rrl` — only UDP makes sense (connection-oriented transports cannot be source-spoofed in the same way) and the server emits a `rateLimited(msg, rinfo, decision)` event for metrics. Truncated responses are sent back to the transport peer, not the (preRequest-overridden) emit client), `Dnssec` (RFC 4034/4035 stateless verifier — `verifyRrsig(owner, rrset, rrsig, dnskey, {now?, skipValidityWindow?})` builds the canonical signing input per §3.1.8.1 then dispatches to Node `crypto.verify` for algorithms 8 RSA/SHA-256, 10 RSA/SHA-512, 13 ECDSA P-256, 14 ECDSA P-384, 15 Ed25519; ECDSA uses `dsaEncoding: 'ieee-p1363'` so DNS raw-r||s round-trips without DER conversion; `computeKeyTag` per RFC 4034 Appendix B; `computeDsDigest`/`verifyDs` for digest types 1/2/4. Canonical RDATA covers wire-already-canonical types (A/AAAA/DS/DNSKEY/TXT/SPF/CAA/TLSA/SSHFP/NSEC3) plus all embedded-name types: NS/CNAME/DNAME/PTR/MX, SOA, SRV, NAPTR (replacement only — char-strings keep case per §6.2 step 2), NSEC, and RRSIG-of-RRSIG. Multi-name types are canonicalized by cloning the record with lowercased name fields and calling the type's existing `encode` (which already builds RDATA in a fresh writer, so no compression leaks in). RFC 4034 §3.1.3 wildcard label-count reconstruction is in `_reconstructSignedOwner`: when `rrsig.labels < owner_label_count` the validator infers `*.<trailing labels>` as the signed owner; `rrsig.labels > owner_label_count` is rejected as malformed per RFC 4035 §5.3.1. For negative answers, the building blocks are exposed: `canonicalNameCompare(a, b)` (RFC 4034 §6.1 right-to-left label-by-label), `nsecCovers(owner, next, query)` (handles end-of-zone wrap-around), `nsec3Hash(name, saltHex, iterations, algorithm=1)` (RFC 5155 §5 SHA-1 with iterations+1 calls — RFC 9276 forbids non-1 algorithms), `nsec3CoversHash(owner, next, query)` (Buffer-compare wrap-around), `base32hexEncode(buf)` (RFC 4648 §7 unpadded). The end-to-end "prove NXDOMAIN with closest-encloser + next-closer + wildcard" composition is left to the caller — it depends on the message-shape conventions a recursive resolver provides. For the authoritative side, `signRrset(owner, rrset, dnskey, privateKey, options)` produces an RRSIG that verifies through `verifyRrsig` by construction — same `buildSigningInput` is used on both sides. `publicKeyToDnskey(publicKey, algorithm)` is the inverse of the verifier's per-algorithm public-key parsers (RFC 3110 RSA, raw-point ECDSA, raw-32-byte Ed25519). `signZone(zone, {ksk, zsk, inception, expiration, dnskeyTtl?, nsec?})` is the convenience wrapper: groups records by lowercased (name, type), synthesizes the DNSKEY RRset at the apex from the provided keys, signs the DNSKEY RRset with the KSK and every other RRset with the ZSK, returns `{records, rrsigs}`. Passing `ksk === zsk` collapses to the CSK case. Wildcard owners sign correctly via `signRrset`'s default — leading `*` is excluded from the labels count per RFC 4034 §3.1.3. With `nsec: true`, an NSEC chain (RFC 4034 §4) is generated covering every owner name in the zone — sorted canonically with `canonicalNameCompare`, wrapping back to the apex, with each name's type bit map listing the types actually present plus RRSIG and NSEC. With `nsec3: {salt?, iterations?, optOut?}` (RFC 5155 / RFC 9276 — defaults: salt empty, iterations 0, opt-out off), the chain instead uses hashed owner names (base32hex(SHA-1(name||salt) iterated)), sorted by hash bytes, with an NSEC3PARAM RR at the apex. NSEC3PARAM is type 51, registered in the type registry. The `nsec` and `nsec3` options are mutually exclusive. Out of scope: chain-of-trust traversal from a trust anchor to the answer's signer).
- **Packet/** — DNS packet model (RFC 1035): header, question, resource record encoding/decoding, domain name compression, class/type enums. `Packet/Zone.ts` is the in-memory zone representation (origin + records + `soa()`, `recordsOfType()`, `fromZoneFile()`, `toAxfrPackets(query, {maxMessageSize?})` for RFC 5936 AXFR — returns a single message when the SOA-bracketed answer set fits under the budget (default 65535, the TCP §4.2.2 length-prefix ceiling), otherwise greedily splits across messages: each frame is built via `new Packet()` (avoids the header-sharing footgun), encoded after every record append, and rolled back when the budget is hit. Same QID/question/`aa=1` on every frame; throws when a single record cannot fit any message of the requested size, and `toIxfrPackets(query, {history?})` for RFC 1995 IXFR — picks no-change / incremental / AXFR-fallback automatically based on the client's serial in the AUTHORITY section and the supplied `ZoneChangeSet[]` history). `Packet/Update.ts` ships `UpdateBuilder` (fluent API for RFC 2136 messages — five prerequisite kinds, four update kinds), `Update.parse/classify*` for the server side, and `Update.applyToZone` as a reference engine that mutates a `Zone` in place and returns the matching `UpdateRcode`. `PacketResource.rdlength` is captured during decode so prerequisite/update markers (rdlength=0) can be distinguished from records that happen to encode small payloads — required because the registered type decoder for e.g. type=A would otherwise produce an `A('')` instance from a 0-length RDATA, which `instanceof UnknownPacketType` doesn't catch.
- **Packet/Types/** — 34 record type implementations (A, AAAA, MX, NS, CNAME, DNAME, PTR, SRV, SOA, TXT, SPF, CAA, EDNS, DNSKEY, DS, CDS, CDNSKEY, NAPTR, NSEC, NSEC3, NSEC3PARAM, RRSIG, SSHFP, TLSA, SMIMEA, SVCB, HTTPS, TSIG, HINFO, URI, ZONEMD, OPENPGPKEY, CERT, LOC), each extending abstract `PacketType`. HTTPS is a thin subclass of SVCB — same RFC 9460 wire format, different type code. CDS / CDNSKEY (RFC 7344) follow the same pattern: subclasses of DS / DNSKEY whose `decode` rebrands the parent's instance — wire format identical, type codes 59 / 60. SMIMEA (RFC 8162) is the same subclass-rebrand pattern over TLSA — wire identical, type code 53. HINFO (RFC 1035 §3.3.2 + RFC 8482 minimal-ANY) carries CPU + OS as two `<character-string>`s. URI (RFC 7553) is `priority + weight + raw-octet target` (no length prefix, consume-to-end). ZONEMD (RFC 8976) is `serial + scheme + hashAlgorithm + digest` (raw digest bytes, hex-encoded internally). OPENPGPKEY (RFC 7929) carries the raw OpenPGP transferable public key bytes. CERT (RFC 4398) is `certType + keyTag + algorithm + certificate-bytes`. LOC (RFC 1876) keeps raw wire-form integers (`version + size + horizPre + vertPre + latitude + longitude + altitude`); presentation-form (deg/min/sec) conversion is left to callers. Used by RFC 8078 child-side automation to push DS changes to the parent. RRSIG has a full encode/decode round-trip; the rdata writer is fresh per RFC 6840 (no compression for DNSSEC RR types) and presentation dates accept either `YYYYMMDDHHMMSS` (UTC) or unsigned-decimal seconds. Unknown types are handled gracefully via `UnknownPacketType`. EDNS dispatches to per-option classes (`EdnsECS`, `EdnsCookie`, `EdnsPadding`, `EdnsNsid`, `EdnsKeepalive`, `EdnsChain`, `EdnsExtendedError`) via the `EdnsOption` interface (each provides `encode(writer)` + static `decode`). `EDNS.createResource(rdata, udpPayloadSize=512, dnssecOk=false)` builds the OPT pseudo-RR; `udpPayloadSize` lands in the CLASS field (RFC 6891 §6.1.2), `dnssecOk` flips the DO bit at TTL `0x00008000` (RFC 3225) — keeping these knobs on the helper avoids every caller hand-rolling the OPT layout. `TXT.decode` preserves character-string boundaries per RFC 1035 §3.3.14 — single-string TXTs decode to `string`, multi-string ones (DNS-SD-style) decode to `string[]` so `key=value` entries don't silently merge.
- **Packet/Types/EdnsChain.ts** — EDNS CHAIN Query Requests option (RFC 7901). Single field `closestTrustPoint`: a DNS name identifying the deepest zone for which the validating client already holds a verified DNSKEY. The server uses it to bundle every signed RRset between that trust point and the answer into one response, collapsing the multi-RTT DNSSEC chain walk. Empty option (length 0) signals "the root". Encoded as an uncompressed DNS name (RFC 7901 §3.1 — fresh BufferWriter prevents cross-option compression).
- **Packet/Types/EdnsCookie.ts** — DNS Cookies (RFC 7873) wire format plus RFC 9018-style server-cookie helpers: `generateClientCookie()`, `computeServerCookie(clientCookie, clientIp, secret, ts?)` returns 24 bytes (1B version + 3B reserved + 4B unix timestamp + 16B truncated HMAC-SHA256), `verifyServerCookie(...)` does a `crypto.timingSafeEqual` against a recomputed cookie and supports an optional `maxAgeSeconds` window.
- **Packet/Tsig.ts, Packet/TsigKey.ts** — TSIG signing + verification (RFC 8945). `TsigKey` holds the shared secret; `Tsig.sign(packet, key)` patches ARCOUNT, computes HMAC (built-in `crypto`) and appends the TSIG RR; `Tsig.verify(packet, receivedBytes, key)` relies on `PacketResource.byteStart` to slice the original wire bytes and does a constant-time MAC check plus fudge-window validation. End-to-end on the server side: handlers receive the post-`preRequest` raw bytes as the 4th arg of the `request` event (and of `ServerRequestHandler`) so verify can use them directly without re-encoding the parsed packet — re-encoding may produce a different name-compression layout that no longer matches the MAC. The `send` callback on UDP/TCP/TLS now accepts `Packet | Buffer | Array<Packet|Buffer>`, so the handler can ship a `Tsig.sign(...).buffer` reply verbatim. `UpdateClient.request(...)`'s call signature accepts `UpdateBuilder | Packet | Buffer` for the same reason.
- **Server/MdnsAnnouncer.ts** — Schedule wrapper around `MdnsServer.announce()`. Handles the post-probe RFC §10 back-off (default `[1000, 2000, 4000, 8000]` ms — Apple-style) plus optional steady-state re-announce interval. `new MdnsAnnouncer(server, records, {schedule?, steadyStateMs?, initialAnnounce?, goodbyeOnStop?}).start()` schedules the chain; `.stop()` cancels pending timers and (default) sends a TTL=0 goodbye via `server.goodbye(records)`. Both `start()` / `stop()` are idempotent. Errors from `server.announce()` are caught and forwarded to `on('error', listener)` if registered, otherwise swallowed — a transient send failure shouldn't kill the schedule. `_announce` reads `this._records` per tick (not a snapshot), so callers can mutate the array between ticks; the records themselves stay immutable since `MdnsServer.announce` copies them before the cache-flush stamp. `running` getter reflects lifecycle state. **Companion fix in MdnsServer._sendUnsolicited**: wrapped `socket.address()` in try/catch so a closed-socket lookup (`ERR_SOCKET_DGRAM_NOT_RUNNING`) becomes a Promise rejection instead of a synchronous throw — that's what announcer ticks expect.
- **Server/MdnsProbe.ts** — RFC 6762 §8 probe/announce helper. `MdnsProbe.claim({records, ...})` runs the dance: random 0..jitter delay → 3 probes 250ms apart (type=ANY, QU bit, tentative records in authority) → on success 2 announcements 1s apart with cache-flush bit on each record's class. Conflict detection on incoming traffic during the probe window: responses (qr=1) carrying our name with rdata not in our tentative set → §8.1 conflict; queries (qr=0) for our name with authority records → simultaneous probe, §8.2 lexicographic tiebreak via `compareRecordSets` (canonical key = type/class/rdata, names excluded per §8.2.1, cache-flush bit stripped). Equal sets compare 0 = no conflict. Plain queries without authority records are not probes and are ignored. `bindPort` separate from `port` — production both default to 5353, tests bind to ephemeral so a peer dgram socket can hold the destination port. Single-name probing: all records must share one owner name; multiple types under same name go in one `claim()` call. `MdnsProbe.canonicalRecordKey` and `MdnsProbe.compareRecordSets` exposed for tiebreak reasoning. Re-probing on conflict is the caller's job — claim() returns and lets the application rename + retry.
- **Server/MdnsServer.ts** — RFC 6762 multicast DNS server. `new MdnsServer({multicastAddr?, port?, family?, interfaceAddress?, joinMulticastGroup?, reuseAddr?})` then `await server.listen()`. Joins the multicast group (autodetected from address; tests pass `127.0.0.1` to disable). Emits `request(packet, send, rinfo, rawRequest)` — 4-arg shape consistent with the rest of the server family, `send(msg, target?)` picks `'multicast'`/`'unicast'`/`'auto'` (auto = unicast when any question on the request carried the QU bit, else multicast). Filters `qr=1` and malformed datagrams before firing `request`. **Unsolicited primitives**: `server.announce(records)` multicasts a NOERROR/AA=1 response with the cache-flush bit (RFC 6762 §10.2) set on every record's class — used post-probe and for periodic re-announce. `server.goodbye(records)` is the same shape but stamps TTL=0 (RFC 6762 §10.1) so peers flush cached entries immediately instead of waiting for natural expiry. Both copy the caller's records before flag/TTL stamping (no mutation), are no-ops on empty arrays, and use the actually-bound port (`socket.address().port`) as destination so test setups with `port: 0` work without a separate `actualPort` field. **Scheduling stays in app code** — the server provides primitives, no built-in periodic announcer. **Out of scope:** continuous-announcement schedule (RFC §10 back-off — provide your own setTimeout chain).
- **Server/CookieGuard.ts** — Transport-neutral DNS Cookie validator (RFC 7873 + RFC 9018). `new CookieGuard(options: ServerCookieOptions)` holds the secret + policy (`mode`, `maxAgeSeconds`, `udpPayloadSize`). `evaluate(message, clientAddress)` returns a discriminated `CookieDecision`: `{action: 'allow', clientCookie, freshServerCookie}` | `{action: 'badcookie', reason, clientCookie, freshServerCookie}` | `{action: 'refused', reason}`. Helpers: `buildCookieOpt`/`attachOrReplaceCookieOpt` for adding/refreshing the cookie option in a response OPT RR (preserves ECS/NSID/padding); `buildBadCookieResponse(request, clientCookie, freshServer)` and `buildRefusedResponse(request)` produce parsed `Packet` reject responses so each transport frames them with its native `_response` path; static `findCookieOption(message)` walks the OPT additionals. `BADCOOKIE_RCODE = 23` exported as the canonical constant. Shared by UDPServer, TCPServer, TLSServer.
- **Server/** — `UDPServer`, `TCPServer`, `TLSServer` (DoT, RFC 7858), `DohServer` (individual protocol servers) and `DnsServer` (combined multi-protocol server). Shared config in `ServerOptions` (with `udp`/`tcp`/`tls`/`doh` blocks). `TLSServer` extends `TCPServer` by overriding two protected hooks (`_loadHooks` reads `options.tls.preRequest`/`preConnection`/`cookies`; `_createInternalServer` returns `tls.createServer(options.tls.options, listener)`); the rest of the framing/handler logic is inherited. Two hook interfaces: `ServerPreRequest<TClient>` (per message) and `ServerPreConnection<TClient>` (per TCP/TLS connection). The `send` callback accepts `Packet | Buffer | Array<Packet|Buffer>`; on TCP/TLS an array writes all packets as length-prefixed frames before closing (used by AXFR), on UDP only the first element is sent. Pre-encoded `Buffer` is the safe path for TSIG-signed replies — the MAC is bound to the exact wire bytes produced by `Tsig.sign`, and re-encoding a parsed Packet may pick different compression. **DNS Cookies** (RFC 7873 + RFC 9018) opt-in via `udp.cookies`/`tcp.cookies`/`tls.cookies: ServerCookieOptions = {secret: Buffer, mode?: 'lenient' | 'strict', maxAgeSeconds?: number, udpPayloadSize?: number}`. All three transports delegate to a `CookieGuard` instance held on the server. Every incoming query is checked for an EDNS Cookie option. Client-only cookies + invalid server cookies get a BADCOOKIE response (rcode 23 — low nibble 7 in the header, upper byte 1 in the OPT TTL via `(rcode >> 4) << 24`) carrying a fresh server cookie; valid cookies pass through with the response auto-attaching/replacing the cookie option in the OPT RR (other OPT options like ECS/NSID/padding preserved). `mode: 'strict'` refuses queries without any cookie option (REFUSED, rcode 5). `mode: 'lenient'` (default) passes them through. Server cookies expire after `maxAgeSeconds` (default 3600, `0` disables expiry check). Rejected queries do NOT reach the request handler — observable via `'cookieRejected'(msg, client, reason)` event where reason is `'no-server-cookie' | 'invalid-cookie' | 'no-cookie-strict'`. Client IP comes from `dgram.RemoteInfo.address` on UDP and from `socket.remoteAddress` on TCP/TLS (preRequest/preConnection-overrides honored), parsed via `IpBytes.parse`. **TCP/TLS cookies semantics**: the handshake is already spoof-resistant, so cookies on TCP add no extra anti-spoofing — value is cross-transport identity (a client falling back UDP→TCP keeps its cookie pair when both share a `ClientCookieJar`) and policy uniformity (`strict` mode applied consistently). UDP cookies pair well with `rrl` for defense-in-depth: cookies handle "first seen, untrusted" cheaply, RRL handles sustained pressure.
- **Lib/IpBytes.ts** — Shared textual-IP → raw-bytes parser. `IpBytes.parseIPv4(str)` (4 bytes), `IpBytes.parseIPv6(str)` (16 bytes, handles `::` zero-compression and `::ffff:1.2.3.4` IPv4-tail form), `IpBytes.parse(str)` auto-detects via colon presence. Throws on malformed input (strict — degenerate values would cause subtle bugs in callers like cookie HMAC or RRL prefix keying). Extracted from `Lib/Rrl.ts` when `UDPServer` cookies needed the same raw-bytes representation; Rrl now delegates to `IpBytes`.
- **Server/ProxyProtocol/** — PROXY protocol v1 (text) and v2 (binary) implementations. `ProxyProtocolV1`/`V2` implement `ServerPreRequest<dgram.RemoteInfo>` for UDP; `ProxyProtocolV1Tcp`/`V2Tcp` implement `ServerPreConnection<net.Socket>` and override `remoteAddress`/`remotePort` via `Object.defineProperty`. `ProxyProtocolTcpReader` is the shared incremental socket-reading helper.
i- **Client/TcpConnectionPool.ts** — RFC 7766 §6.2 connection pool for plain-TCP and TLS DNS. One persistent connection per `(protocol, host, port)` with pipelined ID-based response correlation: each query is rewritten to a unique pool-internal 16-bit DNS header ID before being framed onto the wire and the original is restored on response, so callers can pipeline freely without coordinating IDs. `send(target, queryBytes) => Promise<replyBytes>` is the primitive; `asResolverTransport(defaults?)` is a `RecursiveResolverTransport` adapter for the resolver TC=1 retry path; `TCPClient.request({pool})` is the wiring point for the standalone client. Config: `idleTimeoutMs` (default 10000, RFC 7766 §6.2.4 floor; `0` disables auto-close), `queryTimeoutMs` (5000), `connectTimeoutMs` (5000), `maxQueriesPerConnection` (`0` = no rotation). Errored or peer-closed connections are evicted immediately and re-opened on the next `send()` for that target — only the in-flight queries on the dead socket reject. Length-prefix framing is inlined in `PooledConnection` (rather than via `SocketReader.readStream`, which is one-shot). The constructor attaches a no-op `.catch` to the internal `_ready` Promise so `close()` on an idle/never-queried connection doesn't surface an unhandled rejection. **Out of scope (v1):** multi-connection-per-target (RFC 7766 servers must accept pipelining on a single connection); AXFR / IXFR-fallback (they use socket-end as the SOA-bracketed termination signal — keep using `AxfrClient` directly).
- **Client/ClientCookieJar.ts** — Client-side DNS Cookie store (RFC 7873). Keyed on `${host}:${port}`, allocates a stable 8-byte client cookie per upstream on first contact (RFC 7873 §5.1), learns the server cookie out of each response. `attachTo(query, host, port)` mutates a query packet to carry the cookie EDNS option (adds OPT if absent, preserves other options like ECS/NSID, replaces any existing COOKIE so there's exactly one). `learnFromResponse(response, host, port)` extracts and stores the server cookie. Static helpers: `findCookieOption(message)` walks the OPT additionals; `extendedRcode(response)` joins header rcode (low 4) with OPT TTL upper byte (high 8) per RFC 6891 §6.1.3; `isBadCookie(response)` is the BADCOOKIE (rcode 23) predicate. Wired into UDPClient + TCPClient via `ClientOptions.cookies: boolean | ClientCookieJar` — `true` allocates a private jar; pass an instance to share cookies across multiple `XClient.request(...)` factories. On BADCOOKIE, the client retries the same query exactly once (jar has already learned the fresh server cookie). Since the jar is keyed on `(host, port)`, an UDPClient and a TCPClient pointing at the same `(host, 53)` with a shared jar reuse the same client cookie pair — cross-transport identity per RFC 7873 §5.1. TCPClient retry: opens a fresh connection on the non-pooled path, rides the existing pool connection when `option.pool` is set. Out of scope: DohClient/GoogleClient (DoH fronts terminate resolver identity at the edge anyway).

No-op when `skipHosts: true` is set or there's no hosts file. The watcher mutates the existing HostsFile in place so the `asResolverBackend` closure already wired into the pipeline sees the new entries automatically — no re-wiring needed.
- **Resolver/CachedStubBackend.ts** — `StubResolverBackend` wrapper that adds TTL-aware response caching on top of `DnsCache`. `new CachedStubBackend(upstream, {cache?, cacheOptions?, isCacheable?, now?}).resolve` is the wrapped backend. **Positive caching**: `NOERROR` with answers stored under `(qname, qtype, qclass)` with TTL = `min(record.ttl)` (RFC 1035 §3.7). On hit, synthesizes a fresh response Packet with each record cloned and its TTL decremented by elapsed cache age. **Negative caching** (RFC 2308 §5): `NXDOMAIN` and `NODATA` (NOERROR with empty answers) stored with TTL = `min(SOA.MINIMUM, SOA.TTL)` from the authority section; no SOA → TTL = 0 → effectively not cached. **Not cached by default**: SERVFAIL / REFUSED / FORMERR / NOTIMP — pinning transient failures would mask recovery. Override via `isCacheable` filter (returning `false` skips even cacheable rcodes; returning `true` for non-NOERROR/NXDOMAIN still no-ops because the rcode dispatch is the authoritative store gate). **Authority / additional sections are not preserved** across cache hits — only answers (or empty for negatives). Stale-while-revalidate (RFC 8767) and BIND-style prefetch are inherited from the underlying `DnsCache` — pass `cacheOptions.maxStaleSeconds` / `cacheOptions.prefetchThreshold` and the wrapper returns the cached answer immediately while firing an async background refresh (deduped per `(qname.toLowerCase()|qtype|qclass)` via `_refreshInFlight: Set<string>`; refresh errors silently swallowed). `.cache` accessor exposes the underlying `DnsCache` for `clear()` / `size()` / pre-population.
- **Resolver/FailoverBackend.ts** — multi-upstream failover wrapper for `StubResolverBackend`. `FailoverBackend.combine(backends, {timeoutMs?, attempts?, rotate?, shouldFailover?})` returns a single backend that walks `(server × attempt)` tuples until one returns a non-failover outcome. Default predicate `defaultShouldFailover` matches glibc / BIND: thrown error → fail over, SERVFAIL → fail over, NXDOMAIN/NOERROR/REFUSED/FORMERR/NOTIMP → return immediately. Override via `shouldFailover` (BIND-behind-ACL setups typically also fail over on REFUSED). When all tuples fail, the LAST outcome is surfaced — so a final SERVFAIL response or thrown error reaches the StubResolver above, which halts the search-list walk just like with a single-backend SERVFAIL. Per-attempt timeout via `withTimeout` (Promise.race + setTimeout). Rotation cursor lives in closure scope, advances per call when `rotate: true` (mod backend count). `FailoverBackend.fromConfig(parsedResolvConf, builder, options?)` is the resolv.conf-driven factory: maps each `nameserver` line to a backend via `builder({host, port?})`, wires `options.timeout` (s → ms), `options.attempts`, `options.rotate` from the parsed file. Returns `null` when `parsed.nameservers` is empty so the caller can pick the fallback story (public DNS / throw / etc). **Out of scope:** parallel fan-out, per-server health/circuit-breakers.
- **Resolver/StubResolver.ts** — resolver(5) / glibc-style search-path expander. Pure composition layer over any backend resolver function `(name, type, cls) => Promise<Packet>`. `StubResolver.expand(name)` returns the ordered FQDN candidate list per the classic semantics: trailing dot → absolute only, no expansion; dots ≥ ndots → absolute first then search list; dots < ndots → search list first then absolute; empty search OR ndots=0 → bare name only. `resolve(name, type, cls?)` walks candidates until non-NXDOMAIN — NODATA / SERVFAIL / REFUSED / etc. surface immediately so transient upstream failures aren't masked, NXDOMAIN advances. If every candidate is NXDOMAIN, returns the LAST response (preserves the auth's negative-caching SOA for the longest candidate). `StubResolver.fromConfig(parsedResolvConf, backend)` wires it up from a `Lib/ResolvConf.parse` result, falling back to `[parsed.domain]` as a single-entry search when `parsed.search` is empty (resolver(5) §2 legacy fallback). Search list is normalized — trailing dots stripped, duplicates collapsed. **Out of scope:** nameserver rotation / failover (use `DNS` class), caching (compose with `DnsCache`), `/etc/hosts` lookup.
- **Resolver/** — Iterative recursive resolver. `DnsCache` is a TTL-aware RRset cache with positive + negative entries (RFC 2308), strict-LRU eviction over a `Map`, configurable `min/maxTtlSeconds` clamps (RFC 8767 §6 default ceiling 1 day), and case-insensitive name lookup. `RootHints` bundles the 13 IANA roots (a-m.root-servers.net) with both IPv4 and IPv6 — `seedCache` primes a `DnsCache` with NS + glue, `fromNamedRoot` parses BIND-style `named.root` text for deployments that track the upstream file. `RecursiveResolver` is the engine: starts at the seeded root, walks NS referrals downward, follows CNAME/DNAME chains (default depth 16, BIND-compat), filters every response through `Bailiwick.filter` keyed on the responding server's zone, applies RFC 5452 §9.2 0x20 case randomization with case-echo verification, and enforces a per-resolve `maxQueries` (default 50) and `timeoutMs` (default 10s) budget. Glueless out-of-bailiwick NS trigger a sub-resolution that snapshots `ctx.chain`/`cnameDepth` so it doesn't leak into the caller's CNAME chain — same iteration budget though, so a glue-resolution loop still bounds the work. Transport is injectable via `RecursiveResolverTransport = (ip, port, query) => Promise<Packet>` so the test suite can drive deterministic referral chains without real network access; default is one-shot UDP via Node `dgram`. **TCP fallback on TC=1** (RFC 7766 §5) is on by default: when an upstream replies with the truncation bit set, `_queryServer` reissues the same `Packet` (same wire ID) over `tcpTransport` (default: one-shot length-prefixed connection via Node `net` + `SocketReader`) at `tcpPort` (default 53). The retry runs through the same `_sendAndVerify` path so 0x20 / ID echo is checked again, and counts as one more entry against `maxQueries`. Opt out via `tcpFallback: false` (truncated response is then passed through unmodified). **EDNS(0) buffer negotiation** (RFC 6891) is on by default: every outgoing query carries an OPT RR with `udpPayloadSize` (default 4096) in its CLASS field via `EDNS.createResource([], udpPayloadSize, dnssecOk)`. Opt out via `useEdns: false`; tune via `udpPayloadSize` (1232 for DNS Flag Day 2020 / PMTU-1500 safety). When `dnssec` is enabled the OPT also flips the **DO bit** (RFC 3225 — high bit of the TTL low 16, mask `0x00008000`) so auths return RRSIG / NSEC / NSEC3 records; without DO=1 the validator would never see signatures. **Server-advertised buffer-size respect** (RFC 6891 §6.2.3): every response is scanned for an OPT in additionals; if the server's advertised CLASS is smaller than the resolver's configured size, it gets cached in `_serverBuffers: Map<serverIp, number>` and used as the ceiling for subsequent queries to the same server (only ratcheted down, never up). **Serve-stale (RFC 8767)** is opt-in via `DnsCache({maxStaleSeconds})`: expired entries within the stale window are returned with `stale: true` flag, and `RecursiveResolver._scheduleRefresh` fires a background re-resolution (with `ctx.bypassCache: true` so the refresh actually hits upstream instead of seeing the still-cached stale entry) — concurrent stale hits dedupe via a `_refreshInFlight: Set<string>` keyed on `(qname|qtype|qclass)`. Failed refreshes silently swallow errors so a transient upstream outage doesn't surface to the caller that already got the stale answer. **Prefetch (BIND-style)** is the preemptive variant via `DnsCache({prefetchThreshold})`: still-fresh entries whose remaining/total-TTL ratio is below the configured fraction get flagged with `prefetch: true` and trigger the same `_scheduleRefresh` path — the cached answer stays valid until the refresh completes, so hot keys never see a cold-cache stall. Stale wins over prefetch (an entry past `expiresAt` is `stale`, never `prefetch`); the same in-flight set covers both. Negative answers (NXDOMAIN / NODATA-as-NOERROR-with-SOA) are cached with TTL = `min(SOA.MINIMUM, SOA.TTL)` per RFC 2308 §5. **DNSSEC validation** is opt-in via `dnssec: true | DnssecResolverOptions`: `TrustAnchors` ships the IANA root KSK-2017 anchor and a `findFor`/`findAllFor`/`of` factory (findAllFor returns all anchors tied at the deepest matching zone — needed for RFC 5011 rollover overlap); `DnssecChain.validateDnskeyRrset` walks parent-DS → child-KSK → DNSKEY-RRset, `DnssecChain.validateRrset` validates any RRset against an authenticated DNSKEY set; `NegativeProof.verifyNxdomainNsec`/`verifyNxdomainNsec3` check RFC 4035 §3.1.3.2 / RFC 5155 §8.4 closest-encloser proofs, with `verifyNodataNsec`/`verifyNodataNsec3` for NODATA shapes. Wiring in `RecursiveResolver._dnssecFinalize` walks the chain top-down (`_authenticateZone`), caches per-zone authentication state in `_zoneSecurity`, and on success sets the AD bit (RFC 4035 §3.2: bit 1 of the legacy 3-bit Z field — encoded as `header.z |= 0b010`); on bogus returns SERVFAIL; insecure passes through with AD=0 in permissive mode (default) or SERVFAIL in strict mode. The DS query bypasses normal NS-chasing because DS records live at the *parent* zone (RFC 4035 §5.2) — `_queryDsAtParent` finds the closest NS strictly above the target zone and queries directly. **Insecure-delegation proofs** are verified before the resolver agrees that a zone is unsigned: `_verifyInsecureDelegationProof` validates every NSEC/NSEC3 RRset in the parent's authority section against the parent's DNSKEYs, then runs `NegativeProof.verifyInsecureDelegationNsec` / `verifyInsecureDelegationNsec3` — the NSEC3 path honours the RFC 5155 §6 opt-out flag (bit 0 of `flags`) for both the *match* (NS-but-no-DS bitmap at the delegation hash) and the *cover* (any opt-out-flagged NSEC3 whose hash range brackets the delegation). An empty DS answer without a verifying proof is rejected as bogus to prevent attackers from downgrading signed zones. Auth-chain sub-resolves (DNSKEY/DS) flag `ctx.inAuthChain: true` to suppress nested validation (else infinite recursion). For high-QPS forwarding setups, hand `tcpTransport: pool.asResolverTransport()` from `Client/TcpConnectionPool` so the TC=1 retry path reuses persistent connections instead of one-shot sockets. **QNAME minimization (RFC 9156)** is on by default via `qnameMinimization: true`: at each delegation hop the resolver sends `minimizeQname(qname, nsZone.zone, qnameMinimizationLabelsPerStep)` with `qtype = NS` instead of the full qname — root sees only the TLD label, TLD sees only the SLD, and so on. `minimizeQname` lives in `Resolver/utils.ts`. **Permissive fast path**: when an aa=1 NOERROR response to a probe happens to include records matching `(originalQname, originalQtype)` (RFC 1034 §4.3.4 allows auths to fold extras in), the resolver short-circuits and uses them — saves one roundtrip + accommodates auths that don't differentiate by what was asked. **NXDOMAIN propagation** (RFC 8020 / RFC 9156 §2.3): NXDOMAIN at an ancestor probe is mirrored to the original qname and written to `cache.setNegative(qname, qtype, NXDOMAIN)` so follow-up identical queries short-circuit. **NODATA fallback**: when the probe gets aa=1 NOERROR with no NS in authority (zone has no further delegation), the local `minimizationDisabled` flag is flipped and the next iteration sends the full qname + real qtype to the same NS. **Auth-chain skip**: queries with `ctx.inAuthChain === true` (DNSSEC DNSKEY/DS sub-resolutions) bypass minimization since they already target the exact name they need. Opt out with `qnameMinimization: false` (pre-RFC-9156 behavior — sends full qname at every hop). `qnameMinimizationLabelsPerStep` (default 1) trades leakage for fewer roundtrips per RFC 9156 §3.3.
- **Lib/Dso.ts** — RFC 8490 DNS Stateful Operations wire format. `DsoTlvType` enum (KEEPALIVE=0, RETRY_DELAY=1, ENCRYPTION_PADDING=2, SUBSCRIBE=0x40, PUSH=0x41, UNSUBSCRIBE=0x42, RECONFIRM=0x43). Convenience factories: `DsoMessage.request(id, primary, ...additional)`, `DsoMessage.unilateral(primary)` (ID=0, QR=1 per RFC 8490 §5.4 — used for server-initiated PUSH), `DsoMessage.response(id, rcode, tlvs)`. Each TLV's `encode(writer)` writes `type|length|data`. Length is computed by serializing the data into a fresh BufferWriter first so RFC 8490 §4 "no compression pointers across TLV boundaries" stays enforceable — names inside SUBSCRIBE/RECONFIRM/PUSH are encoded against fresh writers, no cross-record compression in PUSH. - **Client/PushClient.ts** — RFC 8765 DNS Push Notifications client. `new PushClient({host, port?, tls?, requestTimeoutMs?, inactivityMs?, keepaliveMs?, autoReconnect?, reconnectDelayMs?, maxReconnectAttempts?})` — does NOT auto-connect; `await client.subscribe(name, qtype, qclass?) => PushSubscription` lazily opens the TLS connection and sends SUBSCRIBE. Multiple concurrent subscriptions share the TLS connection, each identified by its 16-bit DSO message ID. Lazy connect: first `subscribe()` opens TLS, sends KEEPALIVE TLV with the configured inactivity/keepalive window (RFC 8490 §7.1), then SUBSCRIBE. `PushSubscription` extends EventEmitter — `'push'(records)` fires when matching PUSH arrives (records filtered by case-insensitive trailing-dot-tolerant name + qtype/qclass match with 255 acting as ANY wildcard); `'error'(err)` only fires when a listener is registered (Node EventEmitter rule — emit-error-without-listener crashes the process during normal close); `'close'(err?)` always fires on teardown. **Periodic KEEPALIVE heartbeats**: timer scheduled `keepaliveMs` after each outbound message; fires a fresh KEEPALIVE if the socket stays idle. `keepaliveMs: 0` disables both the initial advertise and the periodic refresh. **`reconfirm(name, type, class, rdata)`** (RFC 8765 §6.5): unacknowledged — server responds via a future PUSH on the relevant subscription. **Auto-reconnect** (`autoReconnect: true`): on socket close with active subscriptions, schedule reconnect using last `RETRY_DELAY` value (or `reconnectDelayMs` fallback); re-open TLS, re-issue SUBSCRIBE for every active subscription (re-keys their `messageId` field — that's why it's mutable, not readonly); emit `'reconnect'` on success or `'reconnectFailed'(err)` after `maxReconnectAttempts`. Server-sent RETRY_DELAY TLVs emit `'retryDelay'(ms)` on the client regardless of `autoReconnect`. `subscription.unsubscribe()` sends UNSUBSCRIBE (RFC 8765 §6.4, unacknowledged — original SUBSCRIBE message ID identifies the subscription). `client.close()` rejects pending requests, clears timers, fires close/error on all subscriptions, destroys the socket.
- **Server/PushServer.ts** — RFC 8765 DNS Push Notifications server. `new PushServer({tls: {cert, key}, inactivityMs?, keepaliveMs?})` + `await server.listen(port?, host?)`. Per-connection state in `PushSession` handling length-prefix framing, per-session subscription map keyed by SUBSCRIBE message ID, frame dispatch on TLV type. Events on the server: `'connection'(session)`, `'subscribe'(tlv, session)` (fired AFTER server acknowledges SUBSCRIBE with rcode=0), `'unsubscribe'(tlv, session)`, `'reconfirm'(tlv, session)` (application decides response — server doesn't auto-reply), `'keepalive'(tlv, session)` (fired when client sends KEEPALIVE — server auto-replies before emitting), `'error'(err)`. `server.notify(records)` iterates every session, matches each record against the session's subscriptions (name normalization + qtype/qclass 255 wildcards), and groups matching records per session before sending one `DsoMessage.unilateral(PushTlv)` per session — returns the count of sessions notified. ### Key Patterns

- **PacketTypeRegistry** is a singleton that maps DNS record type numbers to `PacketType` subclass instances. All 23 types are registered at first access.
- **PacketResource.byteStart** is populated by `PacketResource.decode` with the byte offset of the record in the source buffer. Required by TSIG verification to reconstruct the exact MAC input without re-serializing (which could produce different bytes if DNS compression differs).
- **Buffer operations** are bit-precise but byte-backed. `BufferReader`/`BufferWriter` keep a `Buffer` / `number[]` of bytes plus a bit-offset counter. `read`/`write` take a hot path for byte-aligned 8/16/32-bit fields (Node-native `readUInt*BE` / direct byte stores) and a bit-shift loop for sub-byte fields (1-bit flags and 4-bit OPCODE/RCODE in the 12-byte header). The previous bit-array representation was ~150× slower on encode and ~18× slower on decode for typical packets — when touching this code, preserve the bit-precise semantics (callers like `PacketName.encode` register name-compression offsets via `getByteOffset()`, which still floors the bit length to a byte). `BufferWriter.writeBuffer()` accepts a `Buffer` (byte append) or another `BufferWriter` (bytes + remaining bits).
- **TCP framing** uses 2-byte length prefix per message, handled by `SocketReader`.
- **Servers** emit `request` events as `(packet, send, client, rawRequest)` — same shape across UDP/TCP/TLS/DoH and forwarded by `DnsServer`. The 4th arg is the post-`preRequest` wire bytes that `Packet.parse` saw, exposed for TSIG verification (re-encoding the parsed packet may produce a different name-compression layout that no longer matches the MAC).
- **Pre-hooks** — `preRequest` (per-message) and `preConnection` (TCP/TLS-only, per-connection) are configured via `ServerOptions.udp|tcp|tls|doh`. Both can return a `client` override that the server emits in place of the original. For TCP/TLS `preConnection`, the server passes the returned `initialBuffer` (any bytes read past the PROXY header) to `SocketReader.readStream` so DNS framing continues seamlessly. Responses always go back to the true transport peer; only the emitted client reference is swapped.
- **Clients** follow a factory pattern: `XClient.request(options)` returns an async resolver function `(name, type, cls, options?) => Promise<Packet>`. `UDPClient` automatically retries via `TCPClient` when the response header has the TC (truncation) bit set (RFC 7766 §8); opt out via `tcpFallback: false`, override target with `tcpFallbackPort`. Both `UDPClient` and `TCPClient` (incl. DoT via `protocol: ClientOptionsProtocol.tls`) accept `cookies: boolean | ClientCookieJar` for RFC 7873 client-side cookies — attach the EDNS cookie option per upstream, learn the server cookie out of each response, and retry once on BADCOOKIE (extended rcode 23) with the freshly-issued cookie. `TCPClient.makeQueryPacket` is the Packet-returning sibling of `makeQuery` (for the cookie-attach path); `makeQuery` delegates to it + toBuffer for the unchanged Buffer API. `AxfrClient.request(options)` returns `(zoneName) => Promise<{soa, records}>` and uses TCP/TLS only.
- **`Packet.createResponseFromRequest`** shares the `header` object reference with the request — fine for the common single-response flow but a footgun when you build multiple responses from the same request and want to mutate per-response header fields (e.g. distinct IDs). For multi-packet responses (AXFR-style), build fresh `new Packet()` instances and only copy what's needed.

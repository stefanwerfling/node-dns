# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**dns2ts** — a pure TypeScript DNS server and client library with zero production dependencies. Implements DNS over UDP, TCP, TLS (DoT, RFC 7858), and HTTPS (DoH, RFC 8484), client + server.

## Build & Development Commands

```bash
npm install              # Install dev dependencies
npx tsc                  # Compile TypeScript (src/ -> dist/)
npm test                 # Compile + run all tests (tsc && node dist/Test)
npm run lint             # ESLint check
npm run fix              # ESLint auto-fix
```

Example servers (run after compiling):
```bash
npm run example-server-udp    # Start UDP DNS server
npm run example-server-tcp    # Start TCP DNS server
```

## Architecture

### Module Layout (src/)

- **Lib/HostsFile.ts** — `/etc/hosts` parser + lookup. `HostsFile.parse(content)` / `HostsFile.fromFile(path?)` returns a `HostsFile` instance. Tolerant: malformed lines (no IP, no name, bad address) silently skipped. Names lowercased on parse, lookup is case-insensitive + trailing-dot tolerant. IPv4 (`A`) vs IPv6 (`AAAA`) auto-detected from the address. `lookup(name, type)` returns discriminated union `{kind: 'match', records} | {kind: 'nodata'} | {kind: 'miss'}` — match has at least one record of the requested type, nodata means name is in the file but no record of that type (glibc strict semantics — file is authoritative for present names), miss means name not in file. `asResolverBackend(fallback)` is the StubResolver-shaped adapter: synthesizes NOERROR + AA=1 response on match, NOERROR + empty answers (NODATA shape per RFC 1034 §4.3.2 / RFC 2308 §2.2) on nodata WITHOUT falling through, and only invokes `fallback` on miss. `merge(other)` stacks tables — earlier entries win on collision. `ttl` option (default 0, matches glibc no-cache behavior) stamps synthesized records.
- **Lib/ResolvConf.ts** — resolver(5) `/etc/resolv.conf` parser. `ResolvConf.parse(content)` returns `{nameservers, search, domain?, sortlist, options}`; `fromFile(path?)` is the convenience that reads the standard path. Tolerant: unknown directives are skipped silently, unknown `options` tokens land in `options.unknown`, malformed numeric options fall back to resolver(5) defaults. Last-write-wins for `search` per RFC §3.
- **Lib/** — Low-level I/O and parsers: `BufferReader`/`BufferWriter` for bit-level DNS wire format parsing, `SocketReader` for TCP stream framing (accepts an optional `initialBuffer` so pre-consumed bytes can be fed in), `ZoneParser` for RFC 1035 master file parsing (tokenizer with parens/quotes/comments, `$ORIGIN`/`$TTL`/`$INCLUDE`/`@`, RFC §5.1 leading-whitespace owner-name inheritance, `$INCLUDE` accepts an optional origin override and recurses with a fresh nested state — directives in the included file do not leak back to the parent — file content is read via `fs.readFileSync` against `basePath` by default; pass `includeResolver: (filename, basePath) => string` to load from custom sources; cycles are detected and rejected, RDATA for A/AAAA/NS/CNAME/DNAME/PTR/MX/TXT/SOA/SRV/CAA plus DNSKEY/DS/SSHFP/TLSA/NAPTR/NSEC/NSEC3/RRSIG/SVCB/HTTPS — base32hex helper for NSEC3 next-hashed-owner, generic `TYPEnnn` mnemonic via RFC 3597, `_typeMnemonicToNumber` mapping for NSEC/NSEC3/RRSIG type-bit-maps, RFC 9460 §2.1 SVCB presentation form with `key=value`/quoted/`key=`-then-quoted-token glue and `keyN=` round-trip via `unknown[]`), `Random0x20` (RFC 5452 §9.2 case randomization — `scramble` flips ASCII letters via CSPRNG, `matches` is the case-sensitive verifier; wired into UDPClient/TCPClient via `use0x20: true`), `Bailiwick` (RFC 5452 §6 — `contains(zone, name)` membership predicate, `filter(packet, zone)` strips out-of-zone answer/authority/additional records while preserving questions and EDNS OPT), `Rrl` (RFC 5358-style Response Rate Limiting — token-bucket per (prefix, qtype) bucket; `check(clientIp, qtype, now?)` returns `'allow'|'drop'|'truncate'`; refills at `maxRate` per second, capped at `capacity`; IPv4/IPv6 prefixing default to `/24`/`/56`; slip ratio default 2 — every Nth over-budget query gets a TC=1 hint so legitimate clients fall back to TCP, where source spoofing is hard; `maxBuckets` FIFO-evicts oldest entries to bound memory; built-in IPv4/IPv6 parsers handle `::`-compression and `::ffff:1.2.3.4` IPv4-tail form. UDPServer wires it via `udp.rrl: Rrl` — only UDP makes sense (connection-oriented transports cannot be source-spoofed in the same way) and the server emits a `rateLimited(msg, rinfo, decision)` event for metrics. Truncated responses are sent back to the transport peer, not the (preRequest-overridden) emit client), `Dnssec` (RFC 4034/4035 stateless verifier — `verifyRrsig(owner, rrset, rrsig, dnskey, {now?, skipValidityWindow?})` builds the canonical signing input per §3.1.8.1 then dispatches to Node `crypto.verify` for algorithms 8 RSA/SHA-256, 10 RSA/SHA-512, 13 ECDSA P-256, 14 ECDSA P-384, 15 Ed25519; ECDSA uses `dsaEncoding: 'ieee-p1363'` so DNS raw-r||s round-trips without DER conversion; `computeKeyTag` per RFC 4034 Appendix B; `computeDsDigest`/`verifyDs` for digest types 1/2/4. Canonical RDATA covers wire-already-canonical types (A/AAAA/DS/DNSKEY/TXT/SPF/CAA/TLSA/SSHFP/NSEC3) plus all embedded-name types: NS/CNAME/DNAME/PTR/MX, SOA, SRV, NAPTR (replacement only — char-strings keep case per §6.2 step 2), NSEC, and RRSIG-of-RRSIG. Multi-name types are canonicalized by cloning the record with lowercased name fields and calling the type's existing `encode` (which already builds RDATA in a fresh writer, so no compression leaks in). RFC 4034 §3.1.3 wildcard label-count reconstruction is in `_reconstructSignedOwner`: when `rrsig.labels < owner_label_count` the validator infers `*.<trailing labels>` as the signed owner; `rrsig.labels > owner_label_count` is rejected as malformed per RFC 4035 §5.3.1. For negative answers, the building blocks are exposed: `canonicalNameCompare(a, b)` (RFC 4034 §6.1 right-to-left label-by-label), `nsecCovers(owner, next, query)` (handles end-of-zone wrap-around), `nsec3Hash(name, saltHex, iterations, algorithm=1)` (RFC 5155 §5 SHA-1 with iterations+1 calls — RFC 9276 forbids non-1 algorithms), `nsec3CoversHash(owner, next, query)` (Buffer-compare wrap-around), `base32hexEncode(buf)` (RFC 4648 §7 unpadded). The end-to-end "prove NXDOMAIN with closest-encloser + next-closer + wildcard" composition is left to the caller — it depends on the message-shape conventions a recursive resolver provides. For the authoritative side, `signRrset(owner, rrset, dnskey, privateKey, options)` produces an RRSIG that verifies through `verifyRrsig` by construction — same `buildSigningInput` is used on both sides. `publicKeyToDnskey(publicKey, algorithm)` is the inverse of the verifier's per-algorithm public-key parsers (RFC 3110 RSA, raw-point ECDSA, raw-32-byte Ed25519). `signZone(zone, {ksk, zsk, inception, expiration, dnskeyTtl?, nsec?})` is the convenience wrapper: groups records by lowercased (name, type), synthesizes the DNSKEY RRset at the apex from the provided keys, signs the DNSKEY RRset with the KSK and every other RRset with the ZSK, returns `{records, rrsigs}`. Passing `ksk === zsk` collapses to the CSK case. Wildcard owners sign correctly via `signRrset`'s default — leading `*` is excluded from the labels count per RFC 4034 §3.1.3. With `nsec: true`, an NSEC chain (RFC 4034 §4) is generated covering every owner name in the zone — sorted canonically with `canonicalNameCompare`, wrapping back to the apex, with each name's type bit map listing the types actually present plus RRSIG and NSEC. With `nsec3: {salt?, iterations?, optOut?}` (RFC 5155 / RFC 9276 — defaults: salt empty, iterations 0, opt-out off), the chain instead uses hashed owner names (base32hex(SHA-1(name||salt) iterated)), sorted by hash bytes, with an NSEC3PARAM RR at the apex. NSEC3PARAM is type 51, registered in the type registry. The `nsec` and `nsec3` options are mutually exclusive. Out of scope: chain-of-trust traversal from a trust anchor to the answer's signer).
- **Packet/** — DNS packet model (RFC 1035): header, question, resource record encoding/decoding, domain name compression, class/type enums. `Packet/Zone.ts` is the in-memory zone representation (origin + records + `soa()`, `recordsOfType()`, `fromZoneFile()`, `toAxfrPackets(query, {maxMessageSize?})` for RFC 5936 AXFR — returns a single message when the SOA-bracketed answer set fits under the budget (default 65535, the TCP §4.2.2 length-prefix ceiling), otherwise greedily splits across messages: each frame is built via `new Packet()` (avoids the header-sharing footgun), encoded after every record append, and rolled back when the budget is hit. Same QID/question/`aa=1` on every frame; throws when a single record cannot fit any message of the requested size, and `toIxfrPackets(query, {history?})` for RFC 1995 IXFR — picks no-change / incremental / AXFR-fallback automatically based on the client's serial in the AUTHORITY section and the supplied `ZoneChangeSet[]` history). `Packet/Update.ts` ships `UpdateBuilder` (fluent API for RFC 2136 messages — five prerequisite kinds, four update kinds), `Update.parse/classify*` for the server side, and `Update.applyToZone` as a reference engine that mutates a `Zone` in place and returns the matching `UpdateRcode`. `PacketResource.rdlength` is captured during decode so prerequisite/update markers (rdlength=0) can be distinguished from records that happen to encode small payloads — required because the registered type decoder for e.g. type=A would otherwise produce an `A('')` instance from a 0-length RDATA, which `instanceof UnknownPacketType` doesn't catch.
- **Packet/Types/** — 27 record type implementations (A, AAAA, MX, NS, CNAME, DNAME, PTR, SRV, SOA, TXT, SPF, CAA, EDNS, DNSKEY, DS, CDS, CDNSKEY, NAPTR, NSEC, NSEC3, NSEC3PARAM, RRSIG, SSHFP, TLSA, SVCB, HTTPS, TSIG), each extending abstract `PacketType`. HTTPS is a thin subclass of SVCB — same RFC 9460 wire format, different type code. CDS / CDNSKEY (RFC 7344) follow the same pattern: subclasses of DS / DNSKEY whose `decode` rebrands the parent's instance — wire format identical, type codes 59 / 60. Used by RFC 8078 child-side automation to push DS changes to the parent. RRSIG has a full encode/decode round-trip; the rdata writer is fresh per RFC 6840 (no compression for DNSSEC RR types) and presentation dates accept either `YYYYMMDDHHMMSS` (UTC) or unsigned-decimal seconds. Unknown types are handled gracefully via `UnknownPacketType`. EDNS dispatches to per-option classes (`EdnsECS`, `EdnsCookie`, `EdnsPadding`, `EdnsNsid`, `EdnsKeepalive`, `EdnsExtendedError`) via the `EdnsOption` interface (each provides `encode(writer)` + static `decode`). `EDNS.createResource(rdata, udpPayloadSize=512, dnssecOk=false)` builds the OPT pseudo-RR; `udpPayloadSize` lands in the CLASS field (RFC 6891 §6.1.2), `dnssecOk` flips the DO bit at TTL `0x00008000` (RFC 3225) — keeping these knobs on the helper avoids every caller hand-rolling the OPT layout. `TXT.decode` preserves character-string boundaries per RFC 1035 §3.3.14 — single-string TXTs decode to `string`, multi-string ones (DNS-SD-style) decode to `string[]` so `key=value` entries don't silently merge.
- **Packet/Types/EdnsCookie.ts** — DNS Cookies (RFC 7873) wire format plus RFC 9018-style server-cookie helpers: `generateClientCookie()`, `computeServerCookie(clientCookie, clientIp, secret, ts?)` returns 24 bytes (1B version + 3B reserved + 4B unix timestamp + 16B truncated HMAC-SHA256), `verifyServerCookie(...)` does a `crypto.timingSafeEqual` against a recomputed cookie and supports an optional `maxAgeSeconds` window.
- **Packet/Tsig.ts, Packet/TsigKey.ts** — TSIG signing + verification (RFC 8945). `TsigKey` holds the shared secret; `Tsig.sign(packet, key)` patches ARCOUNT, computes HMAC (built-in `crypto`) and appends the TSIG RR; `Tsig.verify(packet, receivedBytes, key)` relies on `PacketResource.byteStart` to slice the original wire bytes and does a constant-time MAC check plus fudge-window validation. End-to-end on the server side: handlers receive the post-`preRequest` raw bytes as the 4th arg of the `request` event (and of `ServerRequestHandler`) so verify can use them directly without re-encoding the parsed packet — re-encoding may produce a different name-compression layout that no longer matches the MAC. The `send` callback on UDP/TCP/TLS now accepts `Packet | Buffer | Array<Packet|Buffer>`, so the handler can ship a `Tsig.sign(...).buffer` reply verbatim. `UpdateClient.request(...)`'s call signature accepts `UpdateBuilder | Packet | Buffer` for the same reason.
- **Server/MdnsProbe.ts** — RFC 6762 §8 probe/announce helper. `MdnsProbe.claim({records, ...})` runs the dance: random 0..jitter delay → 3 probes 250ms apart (type=ANY, QU bit, tentative records in authority) → on success 2 announcements 1s apart with cache-flush bit on each record's class. Conflict detection on incoming traffic during the probe window: responses (qr=1) carrying our name with rdata not in our tentative set → §8.1 conflict; queries (qr=0) for our name with authority records → simultaneous probe, §8.2 lexicographic tiebreak via `compareRecordSets` (canonical key = type/class/rdata, names excluded per §8.2.1, cache-flush bit stripped). Equal sets compare 0 = no conflict. Plain queries without authority records are not probes and are ignored. `bindPort` separate from `port` — production both default to 5353, tests bind to ephemeral so a peer dgram socket can hold the destination port. Single-name probing: all records must share one owner name; multiple types under same name go in one `claim()` call. `MdnsProbe.canonicalRecordKey` and `MdnsProbe.compareRecordSets` exposed for tiebreak reasoning. Re-probing on conflict is the caller's job — claim() returns and lets the application rename + retry.
- **Server/MdnsServer.ts** — RFC 6762 multicast DNS server. `new MdnsServer({multicastAddr?, port?, family?, interfaceAddress?, joinMulticastGroup?, reuseAddr?})` then `await server.listen()`. Joins the multicast group (autodetected from address; tests pass `127.0.0.1` to disable). Emits `request(packet, send, rinfo, rawRequest)` — 4-arg shape consistent with the rest of the server family, `send(msg, target?)` picks `'multicast'`/`'unicast'`/`'auto'` (auto = unicast when any question on the request carried the QU bit, else multicast). Filters `qr=1` and malformed datagrams before firing `request`. **Unsolicited primitives**: `server.announce(records)` multicasts a NOERROR/AA=1 response with the cache-flush bit (RFC 6762 §10.2) set on every record's class — used post-probe and for periodic re-announce. `server.goodbye(records)` is the same shape but stamps TTL=0 (RFC 6762 §10.1) so peers flush cached entries immediately instead of waiting for natural expiry. Both copy the caller's records before flag/TTL stamping (no mutation), are no-ops on empty arrays, and use the actually-bound port (`socket.address().port`) as destination so test setups with `port: 0` work without a separate `actualPort` field. **Scheduling stays in app code** — the server provides primitives, no built-in periodic announcer. **Out of scope:** continuous-announcement schedule (RFC §10 back-off — provide your own setTimeout chain).
- **Server/** — `UDPServer`, `TCPServer`, `TLSServer` (DoT, RFC 7858), `DohServer` (individual protocol servers) and `DnsServer` (combined multi-protocol server). Shared config in `ServerOptions` (with `udp`/`tcp`/`tls`/`doh` blocks). `TLSServer` extends `TCPServer` by overriding two protected hooks (`_loadHooks` reads `options.tls.preRequest`/`preConnection`; `_createInternalServer` returns `tls.createServer(options.tls.options, listener)`); the rest of the framing/handler logic is inherited. Two hook interfaces: `ServerPreRequest<TClient>` (per message) and `ServerPreConnection<TClient>` (per TCP/TLS connection). The `send` callback accepts `Packet | Buffer | Array<Packet|Buffer>`; on TCP/TLS an array writes all packets as length-prefixed frames before closing (used by AXFR), on UDP only the first element is sent. Pre-encoded `Buffer` is the safe path for TSIG-signed replies — the MAC is bound to the exact wire bytes produced by `Tsig.sign`, and re-encoding a parsed Packet may pick different compression.
- **Server/ProxyProtocol/** — PROXY protocol v1 (text) and v2 (binary) implementations. `ProxyProtocolV1`/`V2` implement `ServerPreRequest<dgram.RemoteInfo>` for UDP; `ProxyProtocolV1Tcp`/`V2Tcp` implement `ServerPreConnection<net.Socket>` and override `remoteAddress`/`remotePort` via `Object.defineProperty`. `ProxyProtocolTcpReader` is the shared incremental socket-reading helper.
i- **Client/TcpConnectionPool.ts** — RFC 7766 §6.2 connection pool for plain-TCP and TLS DNS. One persistent connection per `(protocol, host, port)` with pipelined ID-based response correlation: each query is rewritten to a unique pool-internal 16-bit DNS header ID before being framed onto the wire and the original is restored on response, so callers can pipeline freely without coordinating IDs. `send(target, queryBytes) => Promise<replyBytes>` is the primitive; `asResolverTransport(defaults?)` is a `RecursiveResolverTransport` adapter for the resolver TC=1 retry path; `TCPClient.request({pool})` is the wiring point for the standalone client. Config: `idleTimeoutMs` (default 10000, RFC 7766 §6.2.4 floor; `0` disables auto-close), `queryTimeoutMs` (5000), `connectTimeoutMs` (5000), `maxQueriesPerConnection` (`0` = no rotation). Errored or peer-closed connections are evicted immediately and re-opened on the next `send()` for that target — only the in-flight queries on the dead socket reject. Length-prefix framing is inlined in `PooledConnection` (rather than via `SocketReader.readStream`, which is one-shot). The constructor attaches a no-op `.catch` to the internal `_ready` Promise so `close()` on an idle/never-queried connection doesn't surface an unhandled rejection. **Out of scope (v1):** multi-connection-per-target (RFC 7766 servers must accept pipelining on a single connection); AXFR / IXFR-fallback (they use socket-end as the SOA-bracketed termination signal — keep using `AxfrClient` directly).
- **Client/** — `UDPClient`, `TCPClient` (TCP + TLS), `DohClient` (http/https/h2), `GoogleClient` (Google JSON API), `AxfrClient` (RFC 5936 zone transfer over TCP/TLS — reassembles multi-message replies, terminates on the closing SOA), `IxfrClient` (RFC 1995 incremental transfer — classifies the response into `noChange | incremental | fullAxfr`), `NotifyClient` (RFC 1996 zone-change notification, UDP/TCP/TLS, returns the secondary's ack packet), `UpdateClient` (RFC 2136 dynamic update; takes an `UpdateBuilder`, pre-built `Packet`, or raw `Buffer` — the Buffer overload preserves exact wire bytes for TSIG-signed messages), `MdnsClient` (RFC 6762 multicast DNS — `request({multicastAddr, port, family, timeoutMs, unicastResponse, interfaceAddress, joinMulticastGroup}) => (name, type, cls?) => Promise<MdnsResponse[]>`; sends to `224.0.0.251:5353` IPv4 / `[ff02::fb]:5353` IPv6, listens for `timeoutMs`, returns *array* of responses since mDNS is many-to-many. ID=0 per RFC §18.1, QU bit via `unicastResponse: true` flips top bit of QCLASS, cache-flush bit constant `MDNS_CACHE_FLUSH_BIT=0x8000` exposed. `joinMulticastGroup` auto-detects multicast vs unicast addr — tests drive against `127.0.0.1` without joining a real group. Echoed queries (qr=0) and malformed datagrams are silently filtered), `ServiceDiscovery` (RFC 6763 DNS-SD helper — pure composition over MdnsClient. `browse({serviceType, domain?, timeoutMs?, resolveMissing?, mdns?})` walks PTR → bundled-additionals fast path (RFC 6763 §12) → fallback SRV/TXT/A/AAAA queries for any gaps. `resolveInstance(name, options?)` for a single known instance. TXT decoded per §6.3 — `"flag"` → `true`, `"key=value"` → `'value'`, first-wins on duplicate keys, empty entries skipped. Uses MdnsClient under the hood so all transport options apply). All expose a static `request()` method returning a resolver function.
- **DNS.ts** — High-level resolver that tries multiple nameservers in parallel, supports all protocol types.
- **Resolver/StubResolver.ts** — resolver(5) / glibc-style search-path expander. Pure composition layer over any backend resolver function `(name, type, cls) => Promise<Packet>`. `StubResolver.expand(name)` returns the ordered FQDN candidate list per the classic semantics: trailing dot → absolute only, no expansion; dots ≥ ndots → absolute first then search list; dots < ndots → search list first then absolute; empty search OR ndots=0 → bare name only. `resolve(name, type, cls?)` walks candidates until non-NXDOMAIN — NODATA / SERVFAIL / REFUSED / etc. surface immediately so transient upstream failures aren't masked, NXDOMAIN advances. If every candidate is NXDOMAIN, returns the LAST response (preserves the auth's negative-caching SOA for the longest candidate). `StubResolver.fromConfig(parsedResolvConf, backend)` wires it up from a `Lib/ResolvConf.parse` result, falling back to `[parsed.domain]` as a single-entry search when `parsed.search` is empty (resolver(5) §2 legacy fallback). Search list is normalized — trailing dots stripped, duplicates collapsed. **Out of scope:** nameserver rotation / failover (use `DNS` class), caching (compose with `DnsCache`), `/etc/hosts` lookup.
- **Resolver/** — Iterative recursive resolver. `DnsCache` is a TTL-aware RRset cache with positive + negative entries (RFC 2308), strict-LRU eviction over a `Map`, configurable `min/maxTtlSeconds` clamps (RFC 8767 §6 default ceiling 1 day), and case-insensitive name lookup. `RootHints` bundles the 13 IANA roots (a-m.root-servers.net) with both IPv4 and IPv6 — `seedCache` primes a `DnsCache` with NS + glue, `fromNamedRoot` parses BIND-style `named.root` text for deployments that track the upstream file. `RecursiveResolver` is the engine: starts at the seeded root, walks NS referrals downward, follows CNAME/DNAME chains (default depth 16, BIND-compat), filters every response through `Bailiwick.filter` keyed on the responding server's zone, applies RFC 5452 §9.2 0x20 case randomization with case-echo verification, and enforces a per-resolve `maxQueries` (default 50) and `timeoutMs` (default 10s) budget. Glueless out-of-bailiwick NS trigger a sub-resolution that snapshots `ctx.chain`/`cnameDepth` so it doesn't leak into the caller's CNAME chain — same iteration budget though, so a glue-resolution loop still bounds the work. Transport is injectable via `RecursiveResolverTransport = (ip, port, query) => Promise<Packet>` so the test suite can drive deterministic referral chains without real network access; default is one-shot UDP via Node `dgram`. **TCP fallback on TC=1** (RFC 7766 §5) is on by default: when an upstream replies with the truncation bit set, `_queryServer` reissues the same `Packet` (same wire ID) over `tcpTransport` (default: one-shot length-prefixed connection via Node `net` + `SocketReader`) at `tcpPort` (default 53). The retry runs through the same `_sendAndVerify` path so 0x20 / ID echo is checked again, and counts as one more entry against `maxQueries`. Opt out via `tcpFallback: false` (truncated response is then passed through unmodified). **EDNS(0) buffer negotiation** (RFC 6891) is on by default: every outgoing query carries an OPT RR with `udpPayloadSize` (default 4096) in its CLASS field via `EDNS.createResource([], udpPayloadSize, dnssecOk)`. Opt out via `useEdns: false`; tune via `udpPayloadSize` (1232 for DNS Flag Day 2020 / PMTU-1500 safety). When `dnssec` is enabled the OPT also flips the **DO bit** (RFC 3225 — high bit of the TTL low 16, mask `0x00008000`) so auths return RRSIG / NSEC / NSEC3 records; without DO=1 the validator would never see signatures. **Server-advertised buffer-size respect** (RFC 6891 §6.2.3): every response is scanned for an OPT in additionals; if the server's advertised CLASS is smaller than the resolver's configured size, it gets cached in `_serverBuffers: Map<serverIp, number>` and used as the ceiling for subsequent queries to the same server (only ratcheted down, never up). **Serve-stale (RFC 8767)** is opt-in via `DnsCache({maxStaleSeconds})`: expired entries within the stale window are returned with `stale: true` flag, and `RecursiveResolver._scheduleRefresh` fires a background re-resolution (with `ctx.bypassCache: true` so the refresh actually hits upstream instead of seeing the still-cached stale entry) — concurrent stale hits dedupe via a `_refreshInFlight: Set<string>` keyed on `(qname|qtype|qclass)`. Failed refreshes silently swallow errors so a transient upstream outage doesn't surface to the caller that already got the stale answer. **Prefetch (BIND-style)** is the preemptive variant via `DnsCache({prefetchThreshold})`: still-fresh entries whose remaining/total-TTL ratio is below the configured fraction get flagged with `prefetch: true` and trigger the same `_scheduleRefresh` path — the cached answer stays valid until the refresh completes, so hot keys never see a cold-cache stall. Stale wins over prefetch (an entry past `expiresAt` is `stale`, never `prefetch`); the same in-flight set covers both. Negative answers (NXDOMAIN / NODATA-as-NOERROR-with-SOA) are cached with TTL = `min(SOA.MINIMUM, SOA.TTL)` per RFC 2308 §5. **DNSSEC validation** is opt-in via `dnssec: true | DnssecResolverOptions`: `TrustAnchors` ships the IANA root KSK-2017 anchor and a `findFor`/`of` factory; `DnssecChain.validateDnskeyRrset` walks parent-DS → child-KSK → DNSKEY-RRset, `DnssecChain.validateRrset` validates any RRset against an authenticated DNSKEY set; `NegativeProof.verifyNxdomainNsec`/`verifyNxdomainNsec3` check RFC 4035 §3.1.3.2 / RFC 5155 §8.4 closest-encloser proofs, with `verifyNodataNsec`/`verifyNodataNsec3` for NODATA shapes. Wiring in `RecursiveResolver._dnssecFinalize` walks the chain top-down (`_authenticateZone`), caches per-zone authentication state in `_zoneSecurity`, and on success sets the AD bit (RFC 4035 §3.2: bit 1 of the legacy 3-bit Z field — encoded as `header.z |= 0b010`); on bogus returns SERVFAIL; insecure passes through with AD=0 in permissive mode (default) or SERVFAIL in strict mode. The DS query bypasses normal NS-chasing because DS records live at the *parent* zone (RFC 4035 §5.2) — `_queryDsAtParent` finds the closest NS strictly above the target zone and queries directly. **Insecure-delegation proofs** are verified before the resolver agrees that a zone is unsigned: `_verifyInsecureDelegationProof` validates every NSEC/NSEC3 RRset in the parent's authority section against the parent's DNSKEYs, then runs `NegativeProof.verifyInsecureDelegationNsec` / `verifyInsecureDelegationNsec3` — the NSEC3 path honours the RFC 5155 §6 opt-out flag (bit 0 of `flags`) for both the *match* (NS-but-no-DS bitmap at the delegation hash) and the *cover* (any opt-out-flagged NSEC3 whose hash range brackets the delegation). An empty DS answer without a verifying proof is rejected as bogus to prevent attackers from downgrading signed zones. Auth-chain sub-resolves (DNSKEY/DS) flag `ctx.inAuthChain: true` to suppress nested validation (else infinite recursion). For high-QPS forwarding setups, hand `tcpTransport: pool.asResolverTransport()` from `Client/TcpConnectionPool` so the TC=1 retry path reuses persistent connections instead of one-shot sockets.

### Key Patterns

- **PacketTypeRegistry** is a singleton that maps DNS record type numbers to `PacketType` subclass instances. All 23 types are registered at first access.
- **PacketResource.byteStart** is populated by `PacketResource.decode` with the byte offset of the record in the source buffer. Required by TSIG verification to reconstruct the exact MAC input without re-serializing (which could produce different bytes if DNS compression differs).
- **Buffer operations** are bit-precise but byte-backed. `BufferReader`/`BufferWriter` keep a `Buffer` / `number[]` of bytes plus a bit-offset counter. `read`/`write` take a hot path for byte-aligned 8/16/32-bit fields (Node-native `readUInt*BE` / direct byte stores) and a bit-shift loop for sub-byte fields (1-bit flags and 4-bit OPCODE/RCODE in the 12-byte header). The previous bit-array representation was ~150× slower on encode and ~18× slower on decode for typical packets — when touching this code, preserve the bit-precise semantics (callers like `PacketName.encode` register name-compression offsets via `getByteOffset()`, which still floors the bit length to a byte). `BufferWriter.writeBuffer()` accepts a `Buffer` (byte append) or another `BufferWriter` (bytes + remaining bits).
- **TCP framing** uses 2-byte length prefix per message, handled by `SocketReader`.
- **Servers** emit `request` events as `(packet, send, client, rawRequest)` — same shape across UDP/TCP/TLS/DoH and forwarded by `DnsServer`. The 4th arg is the post-`preRequest` wire bytes that `Packet.parse` saw, exposed for TSIG verification (re-encoding the parsed packet may produce a different name-compression layout that no longer matches the MAC).
- **Pre-hooks** — `preRequest` (per-message) and `preConnection` (TCP/TLS-only, per-connection) are configured via `ServerOptions.udp|tcp|tls|doh`. Both can return a `client` override that the server emits in place of the original. For TCP/TLS `preConnection`, the server passes the returned `initialBuffer` (any bytes read past the PROXY header) to `SocketReader.readStream` so DNS framing continues seamlessly. Responses always go back to the true transport peer; only the emitted client reference is swapped.
- **Clients** follow a factory pattern: `XClient.request(options)` returns an async resolver function `(name, type, cls, options?) => Promise<Packet>`. `UDPClient` automatically retries via `TCPClient` when the response header has the TC (truncation) bit set (RFC 7766 §8); opt out via `tcpFallback: false`, override target with `tcpFallbackPort`. `AxfrClient.request(options)` returns `(zoneName) => Promise<{soa, records}>` and uses TCP/TLS only.
- **`Packet.createResponseFromRequest`** shares the `header` object reference with the request — fine for the common single-response flow but a footgun when you build multiple responses from the same request and want to mutate per-response header fields (e.g. distinct IDs). For multi-packet responses (AXFR-style), build fresh `new Packet()` instances and only copy what's needed.
